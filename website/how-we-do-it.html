Engineering Discipline

How We Do It: Multi-Brain Debate, Strict Contracts & Measurable Gates.

We replace conversational randomness with organizational engineering hierarchy. Every change is debated by specialized brains, contracted via formal task briefs, and verified with real Git diffs.

1. The Multi-Brain Adversarial Local Debate Engine

Before any code is modified, specialized local sub-brains engage in structured debate to protect performance and eliminate bottlenecks:

[Architecture Lead] Tier 0 Proposal

"For day-one local execution, a single-node server with SQLite WAL mode + local directory storage keeps RAM <80MB with zero cloud lock-in. Scale path documented to Tier 3."

[Security Auditor] Adversarial Challenge

"Local storage upload routes must enforce magic-byte MIME validation, path traversal defense, and disk quotas to prevent accidental drive exhaustion."

[Performance Engineer] Latency Challenge

"Local read target p95 < 50ms verified. Recommend optimistic client updates and chunked streaming to prevent UI thread blockage during media playback."

[Product Manager] Consensus Synthesis

"Consensus achieved. Quotas, MIME validation, and optimistic UI merged into docs/SYSTEM_DESIGN.md. Preparing Task Briefs for human approval."

2. The Contract-Driven Protocol (Task Brief $\rightarrow$ Task Report)

Task Brief (Lead $\rightarrow$ Sub-agent)

Strictly bounds work scope to prevent hallucinations and uncontrolled code churn:

ID: [T-001]
Scope: Exact functions/files to modify.
Out of Scope: Unrelated refactoring forbidden.
Skills Assigned: [lean-code, security-audit]
Gates Required: [security, tests, docs]
Task Report (Sub-agent $\rightarrow$ Lead)

Empirical proof of work before a task can ever be marked complete:

Touched Files: Exact path and line ranges.
Diff Excerpt: Real before/after lines.
Verification: Real test runner output pasted.
Gate Status: 0 secrets detected.
Undo: Commit hash or revert command.

4. The 6 Mandatory Quality Gates

Gate 1: Security & Secrets Scanner

Scans every file before git commit. Blocks any API keys, credentials, or private keys.

Gate 2: Unit & Regression Tests

Validates against recorded baseline tests. Zero regressions allowed.

Gate 3: Performance Latency Check

Checks critical paths against the latency budget (read p95 < 50ms [MEASURED]).

Gate 4: Lean-Code Anti-Bloat

Rejects hand-rolled utilities where maintained packages already solve the problem cleanly.

Gate 5: Living Documentation Integrity

Ensures docs/AI_CHANGELOG.md, README, and SYSTEM_DESIGN are synchronized in the same commit.

Gate 6: SEO & Generative Engine Optimization

Generates llms.txt and JSON-LD structured data for AI search engines.
